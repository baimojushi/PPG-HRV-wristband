# v0.3.2 实测验证：采样任务周期性阻塞

## 1. 直接观测

本次 v0.3.1 导出：

```text
样本数                    37060
记录时长                  431.597 s
目标采样率                125.0 Hz
实际有效采样率            85.86 Hz
采样时基 p95 抖动         58.09 ms
长停顿比例                6.26%
长停顿中位数              66.27 ms
长停顿索引间距中位数      16 samples
协议序号缺口              9
```

长停顿严格每约 16 个处理样本出现一次。

v0.3.1 固件同样每 16 个样本执行一次完整 `O(N×lag)` 自相关扫描。
两者周期完全一致，因此将该自相关突发计算定位为采样时基失真的主要根因。

## 2. RR 现状

```text
RR 总数                    580
整段未解决异常            3.28%
最近 60 搏异常            8.33%
最近 60 搏未解决异常      5.00%
```

峰/谷双计数已经解决，剩余 RR 异常明显受 66 ms 周期采样空洞影响。

## 3. v0.3.2 对旧数据的处理

当前旧数据不会被“放宽阈值”强行输出：

```text
SQI                      64.0% / INVALID
时域                     INVALID
频域                     INVALID
```

原因是实际采样时基已经超过 4 ms 硬门。

## 4. 反事实验证：只修采样时基，RR 保持完全相同

把同一批 RR 保留，仅将采样时基视为已经恢复 125 Hz：

```text
时域状态                  LIMITED
RMSSD                     112.97 ms

频域状态                  LIMITED
Total Power               3126.1 ms²
VLF                       1692.8 ms²
LF                        445.5 ms²
HF                        959.1 ms²
LF/HF                     0.464

Welch / Lomb 一致性       82.0%
PCHIP / 线性插值一致性    99.95%
```

这说明当前 RR 数据即使仍含少量孤立异常，频谱本身已经具有较好的双路径一致性。
v0.3.2 的目标是先恢复真实 125 Hz，再允许这类窗口以 `LIMITED` 等级进入计算。

## 5. v0.3.2 修改

- 完整自相关扫描改为每采样固定预算的增量扫描；
- 每采样最多 4 个 lag，每 lag 最多 96 对；
- SQI 对严重有效采样率偏差做硬封顶；
- HRV 增加 `VALID / LIMITED / INVALID` 三级质量门；
- LIMITED 时域仍只使用原始、连续、未修复 NN 对；
- LIMITED 频域要求 Welch–Lomb 与 PCHIP–线性插值同时通过一致性门；
- 采样时基 p95 > 4 ms 时仍禁止正式时频输出。
